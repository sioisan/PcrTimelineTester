# PcrTimelineTester

公主连结公会战调轴工具。载入 PCRCalculator 导出的五人阵容和 Boss 时间轴（`.xlsx`），通过摸轴器的 HTTP `/simulate` 接口比较整场期望伤害。可在 Windows 图形界面或命令行运行。

## 从界面开始

1. 打开 `PcrTimelineTester.exe`，点「打开时间轴…」选择 Excel。使用源码时，安装 Python 3.10+、`httpx` 和 `openpyxl`，在项目目录运行 `.\run.bat gui`。
2. 在左侧「通用设置」填写 PCRCalculator 安装目录和端口。勾选「开始搜索时自动启动摸轴器」可自动启动本地算器，默认端口为 8080。该端口已有算器时会直接复用。
3. 选择优化模式，在「模式参数」调整后点开始。右侧可切换「时间轴」「日志」「结果」。拖动结果表头分隔线调整列宽，超出窗口的部分可横向滚动。点右下角时钟切换白天或黑夜主题，下次启动会沿用。

## 选择优化模式

| 想做什么 | 模式 | 主要输出 |
| --- | --- | --- |
| 微调已有手动轴的 UB 帧，尝试邻近两刀联动或同帧换序 | 逐帧搜索 `frame` | `调帧结果.xlsx` |
| 改变循环，寻找多开或少开 UB 后伤害更高的打法。由AI根据实际轴的优化经验固化成的搜索算法 | 循环搜索 `cycle` | `循环搜索结果.xlsx` |
| 交叉、变异五名角色的语义 UB 序列 | 语义 GA `ga` | `优化结果.xlsx` |
| 从语义轴逐步尝试改刀，允许暂时掉伤 | 退火 `anneal` | `退火结果.xlsx` |
| 在候选池中排完符合分组条件的五人队，比较 AUTO / SET | 阵容搜索 `roster` | `阵容结果.xlsx` |
| 固定队伍，逐刀选择 AUTO / SET | 0押轴 `zero` | `0押结果.xlsx`（逐刀操作和锚点方案） |

**循环搜索**会根据实际 TP 到账、技能命中和 UB 出手帧生成候选，并在下一层重读战斗事件。只有阵容和 Boss 时也可以从自动开场起轴。默认搜索 4 层，每层保留 4 个分支，每支基础候选预算为 64。最高轴从首层起加测相邻 UB 间分段移帧、同帧换序、满 TP 补刀并撤后刀，以及让爆发落入同目标物防或魔防降低的窗口。相容的高分改动会合并后重打整场。连续 4 层持平会转入精调，「分层持平上限」设为 0 可跑满指定层数。想连续改更多步可增加「搜索层数」，想同时保留更多打法可增加「保留分支」。

循环搜索的主结果按整场期望伤害选取。找到比基线多开 UB 的打法时，会从中保留伤害最高和刀数最多的轴，额外文件名形如 `45发分支.xlsx`。相同结果只导出一份。多种子运行时，伤害取均值，实际刀数按首个种子统计。

### 从实测轴归纳出的搜索顺序

1. 用导入表的角色、星级、装备、EX、强化和 Boss 建立基线。已有帧轴从原操作起步，只有队伍时也可从 AUTO/SET 的实放帧起轴。
2. 先改循环。用实际回 TP、溢出、小技能命中和增益边界生成插刀、删刀、换段和充能联动候选。D1 的姬塔能从 8 发变成 9 发，D4 的菲欧多开一发却大幅掉伤，因此主结果始终比较整刀。搜索层保留部分低分或不同实放次数的分支，给后续修轴留机会。
3. 从当前最高轴精调。D3 春姐与菲欧的末发同时提前一帧才产生收益，单改任意一处都持平。程序直接构造相邻队友一起移动的候选，并试相邻 UB 合帧连开、同帧多人换序、小技能结算前后和收尾补刀。D2 和 D5 也有 UB 总数相同、调整时机就提高期望的案例。
4. 每次提升都重新读取最高轴的事件。单刀和相邻队友的同向一帧改动完整扫描，其余每类精调候选每轮最多取「每支候选」条，轮换取样，默认连续两轮持平停止。高分饱和轴可能全程持平。精调把新高候选按实放帧重新模拟，导出后再读回核对。
5. 搜索使用「采样种子数」指定的种子。结束后另按「配对复测种子数」从设定种子开始逐场跑基线和成品，报告平均差、胜场和差值范围，JSON 保存每场明细。D5 曾有蓝字上涨、种子 666 的黑字反而下降的情况，两项分开看。

导出复核发生接口错误或循环轴读回复核不一致时，运行目录会保存 `复核失败-最后候选.xlsx`、失败原因和续跑状态。候选表内标明复核前的评分，可手动导入检查。

在「循环搜索」设置精调持平轮数和配对复测种子数。默认值分别为 2 和 32，设为 0 可分别关闭。也可以直接运行下面的命令。

```powershell
.\run.bat tune 轴.xlsx --mode cycle --set polish_stalls=2 --set review_seeds=1024
```


**0押轴**同时试自身 TP 满和队友 UB 两种操作时机。满 TP 的角色可以在队友 UB 的同一逻辑帧 SET，也可以在该时刻切 AUTO，等正在释放的技能结束。程序只发送前面的操作，读取后续 TP 与自然收招帧，再检查整场的实放帧及同帧顺序。可复现的导入轴也参与起点评分。锚点方案胜出时，结果表列出每刀的触发角色、时机和 SET/AUTO，并写入可重放的帧轴。

**阵容搜索**先分批预载候选池，每场最多引入五个新角色。预载后进行正式评分，查看结果和单队详情均按数值伤害降序排列。操作列按站位显示“角色(O)、角色(X)”。阵容搜索的分组人数是下限。设为「至少 2 人」时，该组可以上 2 至 5 人，只要候选池和其他分组也允许。组间可以重叠。默认每队比较 32 种组合，关闭「每队试 32 种」后只测全 SET。结果按真实站位显示，`O` 表示 SET，`X` 表示 AUTO，最多保留 100 支队伍。

非会战关卡按角色可穿的 EX 类别配装，沿用黎明界的武器和防具方案。勾选攻击、防御、TP 中的任意几项，程序会将每位角色可选的饰品和 AUTO/SET 组合逐一试算。全部留空时使用攻击饰品。在「设置角色饰品」中可为候选池及分组成员指定一种饰品，选「跟随勾选」可解除锁定。攻击与防御使用角色属性对应的虹饰品，TP 使用四条 TP 上升词条。五人全选三种饰品并试 32 种操作时，每个种子共 7,776 场。会战轴自动禁用饰品设置，使用会战 EX。结果表保存获胜阵容的实际配装和首个种子的实放 UB 帧。

## 命令行与结果

在项目目录运行以下命令。算器需已启动，非默认地址用 `--endpoint` 指定。

```powershell
.\run.bat inspect 轴.xlsx
.\run.bat probe 轴.xlsx
.\run.bat tune 轴.xlsx --passes 2
.\run.bat tune 轴.xlsx --mode cycle --set depth=6 --set width=4 --set candidates=96
.\run.bat modes
.\run.bat resume "runs\运行目录名"
```

`--passes` 是逐帧搜索的轮数。每轮使用上一轮的最优帧。`modes` 可列出各模式的参数和默认值。

每次运行单独保存配置、日志、状态和报告。GUI 默认在原轴旁的 `runs\` 下生成结果，正常结束后自动载入结果表。中途停止会保存 `state.json`，可点「续跑…」选择运行目录继续。程序设置、图标缓存和崩溃日志位于 `%LOCALAPPDATA%\PcrTimelineTester\`。
